# Laboratory 1 – Welcome to the Cloud

## Mission Overview

In this activity, I was onboarded as a Junior Cloud Infrastructure Engineer Trainee at CloudNova Technologies. The mission required me to work inside a cloud-based Linux environment using KillerCoda, explore and document the system, organize files and directories, and build a professional GitHub portfolio to track my work for the rest of the semester.

## Objectives

Access a cloud-based Linux environment using KillerCoda. Explore and navigate the Linux operating system. Gather basic system information. Organize files and directories using Linux commands. Create and maintain a professional GitHub repository. Document technical work using Markdown. Demonstrate proper documentation practices used by cloud professionals.

## Activities Performed

Launched an Ubuntu Linux Playground on KillerCoda. Created a new user account lemzabella with a home directory and sudo privileges, then logged in as that user. Recorded the current username, working directory, and hostname. Investigated the Linux environment – checked the distribution, kernel version, CPU information, total memory, and available disk space – and documented the findings in "system-information.md". Created a workspace folder structure (Documents, Notes, Reports, Screenshots) inside the home directory. Created "about-me.md" inside the Notes folder and viewed its contents in the terminal. Created a public GitHub repository (CCM101-lemzabella) and built the required folder/file structure. Documented the mission in this README, including a personal reflection. Captured and organized screenshots as evidence for each checkpoint. Committed and pushed all work to GitHub.

## Linux Commands Used

List commands like "adduser", "usermod", "su", "whoami", "pwd", "hostname", "lsb_release", "uname", "lscpu", "free", "df", "mkdir", "nano", "cat", "git".

## Skills Learned

Navigating and gathering information inside a Linux environment. Creating and managing users, directories, and files via the command line. Writing clear technical documentation in Markdown. Structuring a professional, version-controlled portfolio on GitHub. Following a checkpoint-based workflow similar to real-world cloud engineering onboarding.
